Internal Operations

Internal operations are platform-control-plane workflows for tenant lifecycle, configuration, plans, scheduled jobs, and documentation deployment.

An Organizor administrator uses one platform-realm organizor-admin login to manage every tenant. Tenant identities remain in separate tenant realms, and the backend alone uses the master-realm organizor-provisioner service account to operate Keycloak Admin REST APIs. The administrator does not need tenant-realm or master credentials.

All tenant lifecycle, config, and plan administration endpoints require a platform-issued organizor-admin token. A role of the same name from a tenant realm does not satisfy that policy.

Endpoint Map

Endpoint Purpose
POST /api/admin/tenants/onboard Creates the catalog tenant, its identity realm, database, included modules, and—only when newly created—the one-time default tenant-admin credential (Cache-Control: no-store).
GET /api/admin/tenants Lists all tenants, including soft-deleted tenants.
GET /api/admin/tenants/{id} Loads one tenant by catalog ID.
POST /api/admin/tenants/{id}/upgrade Runs pending tenant database migrations.
DELETE /api/admin/tenants/{id} Disables the tenant realm, then soft-deletes the tenant.
POST /api/admin/tenants/{id}/hard-delete Deletes the tenant realm, then database and catalog record for a previously soft-deleted tenant.
GET /api/admin/tenants/{id}/config Inspects effective tenant config.
GET /api/admin/tenants/{id}/config-overrides Loads explicit tenant overrides.
PUT /api/admin/tenants/{id}/config-overrides Replaces tenant plan assignment and overrides.
GET /api/admin/tenant-plans Lists tenant plans.
PUT /api/admin/tenant-plans/{planKey} Replaces editable tenant plan defaults.

Tenant identity realm mappings are catalog lifecycle data and are not editable through configuration or plan endpoints. Realm failures return TENANT_IDENTITY_PROVIDER_FAILED and stop destructive lifecycle work before database/catalog cleanup.

The Blazor portal exposes control-plane workflows through /admin/tenants and /admin/plans; it does not bypass API authorization. Tenant-admin hosting and login use the same Portal codebase at each tenant's configured portal host, with the tenant realm resolved before OIDC begins.
