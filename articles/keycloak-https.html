Keycloak HTTPS Setup

The development Keycloak container runs over HTTPS at https://localhost:8443. The Blazor WebAssembly portal uses this endpoint for OIDC Authorization Code Flow with PKCE, and the API uses the same realm issuer when validating bearer tokens.

Why HTTPS Is Required

  • The portal runs as a browser application and should not mix HTTPS portal/API calls with HTTP identity-provider redirects.
  • OIDC redirect URIs must match the portal origin exactly.
  • Keycloak 24 runs with explicit hostname and HTTPS configuration when started in production mode.
  • Local HTTPS keeps browser, API, and identity-provider behavior closer to production.

Certificate

The compose file mounts a PKCS#12 certificate from:

keycloak/certs/keycloak.p12

Generate a trusted local certificate with mkcert:

mkcert -install
mkcert -pkcs12 -p12-file .\keycloak\certs\keycloak.p12 localhost

mkcert PKCS#12 files use the password changeit, which matches the Docker Compose configuration.

Keep generated certificates out of source control. If the certificate is missing or not trusted, Keycloak may fail to start or the browser may reject the login page.

Docker Compose

The Keycloak service uses production mode with an HTTPS keystore:

keycloak:
  image: quay.io/keycloak/keycloak:24.0
  command:
    - start
    - --hostname=localhost
    - --https-port=8443
    - --https-key-store-file=/opt/keycloak/conf/keycloak.p12
    - --https-key-store-password=changeit
  volumes:
    - ./keycloak/certs/keycloak.p12:/opt/keycloak/conf/keycloak.p12
  ports:
    - "8443:8443"

Start or restart Keycloak from the repository root:

docker compose down
docker compose up -d

Open the admin console at:

https://localhost:8443

Development admin credentials are configured in docker-compose.yml:

admin / admin

Browser Trust

Chrome and Edge normally trust the mkcert root certificate through the Windows certificate store after mkcert -install.

If Edge still reports ERR_CERT_AUTHORITY_INVALID, import the mkcert root certificate manually into Trusted Root Certification Authorities:

%LOCALAPPDATA%\mkcert\rootCA.pem

Then restart the browser.

Expected Local Endpoints

Component URL
Keycloak https://localhost:8443
Keycloak realm issuer https://localhost:8443/realms/organizor-dev
Portal UI https://localhost:7025
API HTTPS profile https://localhost:7184

The portal and API must both use the HTTPS Keycloak authority. Tokens issued by https://localhost:8443/realms/organizor-dev will not validate against an API configured for the old HTTP Keycloak endpoint. In local development, set both Keycloak:Authority and Keycloak:BaseUrl to HTTPS in API user secrets.

API User Secrets

For local development, verify the API user secrets use HTTPS:

dotnet user-secrets set "Keycloak:Authority" "https://localhost:8443/realms/organizor-dev" --project Code7Dev.Organizor.Api/Code7Dev.Organizor.Api.csproj
dotnet user-secrets set "Keycloak:BaseUrl" "https://localhost:8443" --project Code7Dev.Organizor.Api/Code7Dev.Organizor.Api.csproj

Restart the API after changing these values. Running API processes keep the old configuration in memory.

The development API accepts the local Keycloak certificate for admin-client calls. Browser trust is still required for portal login.

Troubleshooting

Symptom Likely cause Fix
Keycloak does not start Missing keycloak/certs/keycloak.p12 Generate the certificate with mkcert.
Browser rejects Keycloak mkcert root CA is not trusted Run mkcert -install or import the root CA manually.
Portal login redirects fail Keycloak client redirect URI does not include https://localhost:7025/* Update the organizor-ui client redirect URIs.
API returns 401 for portal tokens API Keycloak:Authority still points to HTTP Set authority to https://localhost:8443/realms/organizor-dev.
