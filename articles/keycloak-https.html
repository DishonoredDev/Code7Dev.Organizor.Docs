Keycloak HTTPS Setup

The development Keycloak container runs over HTTPS at https://localhost:8443. The Blazor platform portal, tenant websites, and API must all use this same HTTPS base URL so their realm issuers remain canonical.

The platform portal signs in through organizor-dev. Tenant realms such as tenant-pjsabbe and tenant-tvdk are created by onboarding. The API accepts only the platform issuer and active catalog tenant issuers; it does not use one static API Keycloak:Authority setting.

Why HTTPS Is Required

  • Browser applications should not mix HTTPS portal/API calls with HTTP identity-provider redirects.
  • OIDC redirect URIs must match the browser origin exactly.
  • Keycloak 24 runs with explicit hostname and HTTPS configuration when started in production mode.
  • Local HTTPS keeps browser, API, and identity-provider behavior closer to production.

Certificate

The compose file mounts a PKCS#12 certificate from:

keycloak/certs/keycloak.p12

Generate a trusted local certificate with mkcert:

mkcert -install
mkcert -pkcs12 -p12-file .\keycloak\certs\keycloak.p12 localhost

mkcert PKCS#12 files use a local keystore password. Put that password in .env as ORGANIZOR_KEYCLOAK_HTTPS_KEYSTORE_PASSWORD so it is not committed.

Keep generated certificates out of source control. If the certificate is missing or not trusted, Keycloak may fail to start or the browser may reject the login page.

Docker Compose

The Keycloak service uses production mode with an HTTPS keystore:

keycloak:
  image: quay.io/keycloak/keycloak:24.0
  command:
    - start
    - --hostname=localhost
    - --https-port=8443
    - --https-key-store-file=/opt/keycloak/conf/keycloak.p12
    - --https-key-store-password=${ORGANIZOR_KEYCLOAK_HTTPS_KEYSTORE_PASSWORD:?Set ORGANIZOR_KEYCLOAK_HTTPS_KEYSTORE_PASSWORD in .env}
  volumes:
    - ./keycloak/certs/keycloak.p12:/opt/keycloak/conf/keycloak.p12
  ports:
    - "8443:8443"

Start or restart Keycloak from the repository root:

docker compose --env-file .\.env down
docker compose --env-file .\.env up -d

With an empty Keycloak database, Docker Compose imports only the platform realm resources from docker/keycloak/import/organizor-dev-realm.json. Tenant realms are created by tenant onboarding.

Development Keycloak master-admin credentials are read from the untracked .env file:

ORGANIZOR_KEYCLOAK_ADMIN_USERNAME / ORGANIZOR_KEYCLOAK_ADMIN_PASSWORD

They are used only to bootstrap the backend provisioner after a reset. Organizor administrators do not need a Keycloak master login for normal work.

Backend Provisioner Bootstrap

After a fresh Keycloak start, run:

pwsh ./scripts/bootstrap-keycloak-provisioner.ps1 -SkipCertificateCheck

The script creates or updates confidential, service-account-only client organizor-provisioner in master. It assigns and explicitly scopes the master admin role, then smoke-verifies that its client-credentials token can call the Admin REST API. It does not print the client secret or bearer token.

Configure the API with the matching Keycloak:BaseUrl, Keycloak:PlatformRealm, Keycloak:AdminRealm, Keycloak:AdminClientId, and Keycloak:AdminClientSecret values. See Keycloak Setup for the complete reset and secret configuration steps.

Browser Trust

Chrome and Edge normally trust the mkcert root certificate through the Windows certificate store after mkcert -install.

If Edge still reports ERR_CERT_AUTHORITY_INVALID, import the mkcert root certificate manually into Trusted Root Certification Authorities:

%LOCALAPPDATA%\mkcert\rootCA.pem

Then restart the browser.

Expected Local Endpoints

Component URL
Keycloak base URL https://localhost:8443
Platform realm issuer https://localhost:8443/realms/organizor-dev
Tenant realm issuer pattern https://localhost:8443/realms/tenant-{slug}
Portal UI https://localhost:7025
API HTTPS profile https://localhost:7184

The central portal's browser configuration uses the platform authority https://localhost:8443/realms/organizor-dev. Tenant websites must use the tenant authority returned from GET /api/public/tenants/{slug}/auth.

The API configuration uses the HTTPS base URL, not a fixed realm authority. Keycloak:BaseUrl must therefore be https://localhost:8443; an API configured with the old HTTP base URL rejects HTTPS-issued tokens because the issuer does not match.

API User Secrets

For local development, configure the API after bootstrap:

dotnet user-secrets set "Keycloak:BaseUrl" "https://localhost:8443" --project Code7Dev.Organizor.Api/Code7Dev.Organizor.Api.csproj
dotnet user-secrets set "Keycloak:PlatformRealm" "organizor-dev" --project Code7Dev.Organizor.Api/Code7Dev.Organizor.Api.csproj
dotnet user-secrets set "Keycloak:AdminRealm" "master" --project Code7Dev.Organizor.Api/Code7Dev.Organizor.Api.csproj
dotnet user-secrets set "Keycloak:AdminClientId" "organizor-provisioner" --project Code7Dev.Organizor.Api/Code7Dev.Organizor.Api.csproj
dotnet user-secrets set "Keycloak:AdminClientSecret" "<value from .env>" --project Code7Dev.Organizor.Api/Code7Dev.Organizor.Api.csproj

Restart the API after changing these values. Running API processes keep the old configuration in memory.

The development API accepts the local Keycloak certificate for metadata and admin-client calls. Browser trust is still required for portal and tenant website login.

Troubleshooting

Symptom Likely cause Fix
Keycloak does not start Missing keycloak/certs/keycloak.p12 Generate the certificate with mkcert.
Browser rejects Keycloak mkcert root CA is not trusted Run mkcert -install or import the root CA manually.
Portal login redirects fail Platform client redirect URI does not include https://localhost:7025/* Update the platform-realm organizor-ui client redirect URIs.
Tenant website login redirects fail The tenant website client has stale redirect URIs or authority. Re-onboard/update the tenant settings and use its public auth contract.
API returns 401 for a valid token API Keycloak:BaseUrl uses HTTP, the issuer is not an active platform/tenant realm, or the audience is missing. Use https://localhost:8443, verify the tenant is active, and request an organizor-api audience token.
Provisioner bootstrap fails Master admin credentials, provisioner values, or local certificate are wrong. Correct .env, wait for Keycloak startup, then rerun the script; it is safe to rerun.
