Local Development

This page is the canonical reference for running Organizor locally. Use it to confirm the expected ports, startup order, and how the Blazor portal, Keycloak, API, and databases fit together.

Ports And URLs

Component URL Notes
Portal UI https://localhost:7025 Blazor WebAssembly HTTPS launch profile.
Portal UI HTTP http://localhost:5080 Development fallback profile. Prefer HTTPS for auth testing.
Organizor API https://localhost:7184 API HTTPS launch profile used by the portal.
Organizor API HTTP http://localhost:5100 Useful for direct local API calls without the portal.
Keycloak https://localhost:8443 Docker Compose service with local HTTPS certificate.
Keycloak realm issuer https://localhost:8443/realms/organizor-dev Must match API Keycloak:Authority.
Keycloak token endpoint https://localhost:8443/realms/organizor-dev/protocol/openid-connect/token Used for manual token testing.

Required Local Configuration

The API needs:

  • a ConnectionStrings:Catalog connection string;
  • Postgres settings for tenant database creation and resolution;
  • Keycloak:Authority set to https://localhost:8443/realms/organizor-dev;
  • Keycloak:BaseUrl set to https://localhost:8443;
  • Keycloak:Realm set to organizor-dev;
  • Keycloak:AdminClientId set to organizor-api;
  • Keycloak:AdminClientSecret from the Keycloak organizor-api client.
Warning

The API authority must match the token issuer exactly. A token issued by https://localhost:8443/realms/organizor-dev will not validate against any different scheme, host, port, or realm.

The portal is currently configured to:

  • use Keycloak authority https://localhost:8443/realms/organizor-dev;
  • use Keycloak client ID organizor-ui;
  • redirect login callbacks to https://localhost:7025/authentication/login-callback;
  • call the API at https://localhost:7184.

Startup Order

  1. Generate or verify the Keycloak HTTPS certificate at keycloak/certs/keycloak.p12.
  2. Start Keycloak with Docker Compose.
  3. Confirm the organizor-dev realm, clients, roles, groups, and users exist.
  4. Start the API with the HTTPS launch profile.
  5. Start the portal with the HTTPS launch profile.
  6. Sign in through the portal and verify the API accepts the issued token.

Commands

Start Keycloak:

docker compose up -d

Run the API:

dotnet run --project .\Code7Dev.Organizor.Api\Code7Dev.Organizor.Api.csproj --launch-profile https

Run the portal:

dotnet run --project .\Code7Dev.Organizor.Portal.Ui\Code7Dev.Organizor.Portal.Ui.csproj --launch-profile https

Build the documentation:

docfx .\docs\docfx.json

Keycloak Client Requirements

The organizor-ui client must allow the portal origin:

Setting Value
Valid redirect URI https://localhost:7025/*
Login callback https://localhost:7025/authentication/login-callback
Web origin https://localhost:7025

The organizor-api client is used for API service-account operations during tenant onboarding and hard deletion. Its client secret must be available to the API through configuration or user secrets.

Production Checklist

Do not copy local wildcard origins, local certificates, or development secrets into deployed environments. Production should use real HTTPS certificates, explicit origins, and managed secret storage.

Verification Checklist

Use this checklist when local authentication or API calls fail:

  • Keycloak opens at https://localhost:8443 without a certificate warning.
  • The API Keycloak:Authority exactly matches https://localhost:8443/realms/organizor-dev.
  • The portal login callback is allowed by the organizor-ui client.
  • The portal calls https://localhost:7184, not the API HTTP endpoint.
  • The API HTTPS profile is running before logging in through the portal.
  • The signed-in user has the expected realm roles and tenant groups.
  • The portal user information panel shows the expected tenant, preferred_username, email, and groups claim values.
