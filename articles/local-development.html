Local Development

This page is the canonical reference for running Organizor locally. Use it to confirm the expected ports, startup order, and how the Blazor portal, Keycloak, API, and databases fit together.

Required Local Configuration

Copy .env.example to .env and fill the local Keycloak container credentials before running Docker Compose. Keep .env untracked. If your .env predates tenant realm isolation, add the new ORGANIZOR_KEYCLOAK_PROVISIONER_CLIENT_ID and ORGANIZOR_KEYCLOAK_PROVISIONER_CLIENT_SECRET entries from .env.example; existing .env files are not updated automatically.

The API needs:

  • a ConnectionStrings:Catalog connection string;
  • Postgres settings for tenant database creation and resolution;
  • Keycloak:BaseUrl set to https://localhost:8443;
  • Keycloak:PlatformRealm set to organizor-dev;
  • optionally Keycloak:AdminRealm set explicitly to master (it defaults to master);
  • Keycloak:AdminClientId set to organizor-provisioner;
  • Keycloak:AdminClientSecret from the local provisioner settings in .env.
  • optionally Keycloak:DefaultTenantAdminTemporaryPassword for predictable local-only tenant admin testing; omit it to generate a random temporary password. A newly created default tenant-admin credential is shown only in the successful portal onboarding notice, so copy it before dismissing the notice.
  • Keycloak:DevelopmentAdmin:Username and Keycloak:DevelopmentAdmin:Email for the local platform admin identity.
  • Keycloak:DevelopmentAdmin:Password when you want API startup to seed the local platform admin with the organizor-admin role.
Warning

The API accepts only its configured platform issuer and active catalog tenant issuers. A tenant token must be issued by the realm owned by the tenant in X-Tenant-Slug.

At https://localhost:7025, the Portal is configured to:

  • use Keycloak authority https://localhost:8443/realms/organizor-dev;
  • use Keycloak client ID organizor-ui;
  • redirect login callbacks to https://localhost:7025/authentication/login-callback;
  • call the API at https://localhost:7184.

At a tenant portal host such as https://localhost:7022, the same Portal first resolves GET /api/public/tenant-portals/auth?baseUrl=https%3A%2F%2Flocalhost%3A7022, validates the returned host/callback/origin values, and then uses the resolved tenant realm and tenant-tvdk-portal client. Portal:PlatformBaseUrl identifies the one fixed platform host. These portal values live in Code7Dev.Organizor.Portal.Ui/wwwroot/appsettings.json for local development and must be replaced with deployment URLs for server environments.

The separate TVDK tenant website must discover its authority and client id from GET /api/public/tenants/tvdk/auth, then send X-Tenant-Slug: tvdk on authenticated API calls. Its former static shared-realm configuration needs that coordinated update before it is used with this identity model.

Startup Order

  1. Generate or verify the Keycloak HTTPS certificate at keycloak/certs/keycloak.p12.
  2. Start Keycloak with Docker Compose.
  3. On an empty Keycloak database, Docker Compose imports docker/keycloak/import/organizor-dev-realm.json and creates the platform realm, clients, roles, and local platform admin user.
  4. Run pwsh ./scripts/bootstrap-keycloak-provisioner.ps1 -SkipCertificateCheck to create the master-realm backend provisioner. The switch is restricted to the local loopback Keycloak URL; omit it when the local certificate is trusted by PowerShell.
  5. Start the API with the HTTPS launch profile.
  6. Start the portal with the HTTPS launch profile.
  7. Sign in through the platform portal, onboard a tenant, and verify its public auth contract returns a tenant-specific authority.

Commands

Start Keycloak:

Copy-Item .\.env.example .\.env
docker compose --env-file .\.env up -d

Run Docker Compose commands from the repository root. From the docs folder, use:

docker compose --project-directory .. --env-file ..\.env up -d

Reset local Keycloak identity data only when you intentionally want a fresh realm import. This does not delete the API catalog database or tenant PostgreSQL databases:

docker compose --env-file .\.env down -v
docker compose --env-file .\.env up -d

From the docs folder:

docker compose --project-directory .. --env-file ..\.env down -v
docker compose --project-directory .. --env-file ..\.env up -d

docker compose down -v deletes the local Keycloak database volume. The next startup imports docker/keycloak/import/organizor-dev-realm.json again. Run the provisioner bootstrap script after every Keycloak-only reset, then configure API user secrets:

dotnet user-secrets set "Keycloak:BaseUrl" "https://localhost:8443" --project .\Code7Dev.Organizor.Api\Code7Dev.Organizor.Api.csproj
dotnet user-secrets set "Keycloak:PlatformRealm" "organizor-dev" --project .\Code7Dev.Organizor.Api\Code7Dev.Organizor.Api.csproj
dotnet user-secrets set "Keycloak:AdminRealm" "master" --project .\Code7Dev.Organizor.Api\Code7Dev.Organizor.Api.csproj
dotnet user-secrets set "Keycloak:AdminClientId" "organizor-provisioner" --project .\Code7Dev.Organizor.Api\Code7Dev.Organizor.Api.csproj
dotnet user-secrets set "Keycloak:AdminClientSecret" "<value from .env>" --project .\Code7Dev.Organizor.Api\Code7Dev.Organizor.Api.csproj
dotnet user-secrets set "Keycloak:DevelopmentAdmin:Username" "admin@organizor.dev" --project .\Code7Dev.Organizor.Api\Code7Dev.Organizor.Api.csproj
dotnet user-secrets set "Keycloak:DevelopmentAdmin:Email" "admin@organizor.dev" --project .\Code7Dev.Organizor.Api\Code7Dev.Organizor.Api.csproj
dotnet user-secrets set "Keycloak:DevelopmentAdmin:Password" "<local-only-password>" --project .\Code7Dev.Organizor.Api\Code7Dev.Organizor.Api.csproj

The development admin seeder creates the configured platform admin when missing and assigns the organizor-admin role. It does not reset an existing password unless Keycloak:DevelopmentAdmin:ResetPasswordOnStartup is set to true.

The realm import also creates admin@organizor.dev with password Admin123! and realm role organizor-admin for local development. If the API starts before Keycloak finishes a fresh import, it logs a warning and continues; restart the API after Keycloak is ready if you need the API seeder to repair the user.

Keep Docker Compose values in .env. Keep API development-admin values in user secrets; user secrets are loaded automatically in Development.

Full Local Test Reset (Destructive)

Use this procedure only for an intentionally disposable local test environment. It permanently deletes all local Keycloak identities, the Organizor catalog, and every local tenant database. It must never be used against shared, staging, or production PostgreSQL servers.

  1. Stop the local API and portal so they do not keep PostgreSQL connections open.

  2. Type the following confirmation in PowerShell before continuing:

    $confirmation = Read-Host 'Type RESET-ORGANIZOR-LOCAL to erase local Keycloak, catalog, and tenant data'
if ($confirmation -cne 'RESET-ORGANIZOR-LOCAL') { throw 'Full reset cancelled.' }

  3. Reset the Keycloak Docker volume:

    docker compose --env-file .\.env down -v

  4. Connect to the local test PostgreSQL server's postgres database with an administrator role from your Postgres/Catalog development configuration. First inventory the exact databases that will be removed:

    SELECT datname
FROM pg_database
WHERE datname = 'organizor_catalog'
   OR datname LIKE 'organizor_tenant_%'
ORDER BY datname;

  5. Verify the result contains only disposable local Organizor databases. Then run one explicit statement for every listed tenant database, followed by the catalog. For example:

    DROP DATABASE IF EXISTS "organizor_tenant_tvdk" WITH (FORCE);
DROP DATABASE IF EXISTS "organizor_tenant_pjsabbe" WITH (FORCE);
DROP DATABASE IF EXISTS "organizor_catalog" WITH (FORCE);

    Do not replace the explicit names with a broad wildcard or run these commands on a non-local server. WITH (FORCE) disconnects local test clients.

  6. Start Keycloak again, wait for its health/startup to complete, then bootstrap the provisioner:

    docker compose --env-file .\.env up -d
pwsh ./scripts/bootstrap-keycloak-provisioner.ps1 -SkipCertificateCheck

  7. Start the API. It recreates and migrates the empty catalog. Sign in through the platform portal, onboard new test tenants with both their public website and tenant-admin portal URLs, and obtain each tenant website's realm authority from public auth discovery.

The API PostgreSQL server is not managed by docker-compose.yml; only the Keycloak PostgreSQL volume is. That is why both the Docker reset and the explicit catalog/tenant database reset are required for a true clean test environment.

Run the API:

dotnet run --project .\Code7Dev.Organizor.Api\Code7Dev.Organizor.Api.csproj --launch-profile https

Run the portal:

dotnet run --project .\Code7Dev.Organizor.Portal.Ui\Code7Dev.Organizor.Portal.Ui.csproj --launch-profile https

Run the tenant-admin portal profile after onboarding TVDK with tenantAdminPortalBaseUrl set to https://localhost:7022:

dotnet run --project .\Code7Dev.Organizor.Portal.Ui\Code7Dev.Organizor.Portal.Ui.csproj --launch-profile tenant-https

Build the documentation:

docfx .\docs\docfx.json

Generate a local documentation deploy key only when you need to update the GitHub DOCS_DEPLOY_KEY secret:

New-Item -ItemType Directory -Force .\ssh
ssh-keygen -t ed25519 -C "organizor-docs-deploy" -f .\ssh\organizor-docs-key

The private key stays at ssh/organizor-docs-key and ssh/ is gitignored. Do not commit, copy into docs output, or delete this folder unless you are intentionally rotating the deploy key. Store the private key value in the GitHub Actions secret DOCS_DEPLOY_KEY, and add the public key ssh/organizor-docs-key.pub as a deploy key on the public documentation repository.

Keycloak Client Requirements

The organizor-ui client must allow the portal origin:

Setting Value
Valid redirect URI https://localhost:7025/*
Login callback https://localhost:7025/authentication/login-callback
Web origin https://localhost:7025

After TVDK is onboarded, its realm-local tenant-tvdk-web client must allow the local TVDK origin:

Setting Value
Valid redirect URI https://localhost:7122/authentication/login-callback
Web origin https://localhost:7122
Post-logout redirect URI https://localhost:7122/

If the TVDK sign-in flow shows Invalid parameter: redirect_uri, update the tenant-tvdk-web client in the tenant-tvdk realm with the exact callback URI above. For HTTP-profile testing, also allow http://localhost:5085/authentication/login-callback, http://localhost:5085, and http://localhost:5085/. The TVDK website must still discover its authority and client id from GET /api/public/tenants/tvdk/auth rather than hard-coding the platform realm.

The same onboarding also creates tenant-tvdk-portal in tenant-tvdk for the tenant-admin Portal host:

Setting Value
Valid redirect URI https://localhost:7022/authentication/login-callback
Post-logout redirect URI https://localhost:7022
Web origin https://localhost:7022

The portal client is distinct from tenant-tvdk-web; do not merge their redirect/origin settings.

The backend-only organizor-provisioner client in the Keycloak master realm performs API service-account operations during tenant onboarding and deletion. pwsh ./scripts/bootstrap-keycloak-provisioner.ps1 -SkipCertificateCheck explicitly maps and scopes its master admin role, then smoke-verifies an Admin REST call without printing its secret or token. The certificate-bypass switch is allowed only for loopback URLs. Keep that client secret only in API configuration or deployment secrets.

Production Checklist

Do not copy local wildcard origins, local certificates, or development secrets into deployed environments. Production should use real HTTPS certificates, explicit origins, and managed secret storage.

Verification Checklist

Use this checklist when local authentication or API calls fail:

  • Keycloak opens at https://localhost:8443 without a certificate warning.
  • The API Keycloak:BaseUrl is exactly https://localhost:8443, Keycloak:PlatformRealm is organizor-dev, and the provisioner settings point to master / organizor-provisioner.
  • The portal login callback is allowed by the organizor-ui client.
  • The TVDK login callback is allowed by the tenant-tvdk-web client when testing the separate tenant website.
  • The portal calls https://localhost:7184, not the API HTTP endpoint.
  • The API HTTPS profile is running before logging in through the portal.
  • A platform portal token has organizor-admin from the platform realm and the organizor-api audience.
  • A tenant website token has realm-local tenant roles, the organizor-api audience, and an issuer matching its X-Tenant-Slug; its optional tenant claim is not used as the access boundary.
