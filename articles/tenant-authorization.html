Tenant Authorization

Overview

Tenant-scoped API routes require both a valid JWT and an X-Tenant-Slug header. The API resolves the header to a catalog tenant, validates that the JWT is allowed to use that tenant, then lets controller authorization policies run.

Tenant Resolution

Tenant-scoped routes must include:

X-Tenant-Slug: acme

The tenant resolution middleware skips platform and infrastructure routes, including:

  • /api/admin
  • /api/public
  • /api/v1/tenants
  • /api/auth
  • /health
  • /openapi
  • /scalar
  • /favicon
  • /robots

Resolution steps:

  1. Middleware reads X-Tenant-Slug.
  2. Middleware looks up the tenant in the catalog database.
  3. Middleware sets tenantContext.Current.
  4. Middleware logs tenant metadata.

JWT Tenant Claim

Tenant membership is represented by one or more tenant claims. The middleware accepts either direct slugs or Keycloak-style paths:

{
  "tenant": ["/tenants/acme/admins", "/tenants/contoso/users"]
}

The slug is extracted from the segment after /tenants/. For /tenants/acme/admins, the effective tenant slug is acme.

Static tenant websites discover the expected tenant header and claim names through GET /api/public/tenants/{slug}/auth. That endpoint is anonymous and bypasses tenant resolution; authenticated tenant-scoped calls still require X-Tenant-Slug.

Enforcement Rules

For tenant-scoped routes:

  • Missing or invalid Authorization returns 401 Unauthorized when the endpoint requires [Authorize].
  • Missing endpoint roles such as tenant-user or tenant-admin returns 403 Forbidden.
  • Missing X-Tenant-Slug returns 400 Bad Request.
  • Unknown X-Tenant-Slug returns 404 Not Found.
  • A JWT with tenant claims must include the same slug as X-Tenant-Slug.
  • A JWT tenant/header mismatch returns 403 Forbidden.
  • A JWT without tenant claims is treated as a platform superadmin token and bypasses tenant membership checks.
  • The organizor-api service account, identified by client_id = organizor-api, bypasses tenant membership checks.
  • Matching tenant JWTs are still checked through ITenantAccessService.UserHasAccessAsync(userId, tenantId).
  • If ITenantAccessService denies access, the API returns 403 Forbidden.

Sample Requests

Tenant-scoped request:

GET http://localhost:5100/api/some-tenant-scoped-route
Authorization: Bearer <tenant-token>
X-Tenant-Slug: acme
Accept: application/json

Cross-tenant denial:

GET http://localhost:5100/api/some-tenant-scoped-route
Authorization: Bearer <token-with-tenant-acme>
X-Tenant-Slug: contoso
Accept: application/json

Superadmin bypass:

GET http://localhost:5100/api/some-tenant-scoped-route
Authorization: Bearer <token-without-tenant-claim>
X-Tenant-Slug: acme
Accept: application/json
