Tenant Authorization

Overview

Tenant-scoped API routes require a valid bearer token and an X-Tenant-Slug header. The catalog maps that slug to a tenant database and an immutable Keycloak realm. The API then requires the token issuer to match that realm.

Tenant Resolution

Tenant-scoped routes include:

X-Tenant-Slug: acme

Resolution reads the active catalog tenant and stores its id, slug, and IdentityRealm in the request tenant context. Platform routes, public routes, and health/documentation routes bypass tenant resolution.

Enforcement Rules

For a tenant-scoped route:

  • a tenant-acme token may call only requests resolved as acme;
  • a tenant-contoso token calling X-Tenant-Slug: acme receives 403 Forbidden;
  • a platform-realm token is cross-tenant only when it carries organizor-admin;
  • the old no-tenant-claim superadmin bypass does not exist;
  • the tenant claim is informational compatibility data, not an access decision;
  • an organizor-api service-account token does not bypass issuer binding merely because it is a service account.

Middleware Chain

flowchart TD

    D --> E[Issuer-aware role policy]
    E --> F[Controller]
