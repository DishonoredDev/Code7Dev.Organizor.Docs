Tenant Config Operations

All admin endpoints on this page require a bearer token satisfying the organizor-admin role policy.

Important

These compatibility routes manage effective legacy configuration and plan assignment. They do not install, enable, disable, or entitle modules. Use Tenant Modules for module lifecycle operations.

Effective Config

GET /api/admin/tenants/{id}/config
Authorization: Bearer <organizor-admin-token>

Returns effective config for one tenant. Effective config is resolved from system defaults, the tenant's assigned plan defaults, and tenant-level overrides.

Tenant admins can view their own effective config through the tenant-scoped endpoint:

GET /api/v1/tenant/config
Authorization: Bearer <tenant-admin-token>
X-Tenant-Slug: acme

Tenant Overrides

GET /api/admin/tenants/{id}/config-overrides
Authorization: Bearer <organizor-admin-token>

Returns only explicit tenant-level overrides.

PUT /api/admin/tenants/{id}/config-overrides
Authorization: Bearer <organizor-admin-token>
Content-Type: application/json

{
  "planKey": "pro",
  "features": {
    "branding.customLogo": true
  },
  "settings": {
    "limits": {
      "maxUsers": 25
    }
  }
}

Override updates replace the tenant's full assigned plan key, legacy feature override dictionary, and setting override dictionary. Omitted override keys are removed and inherited again from the assigned plan or system defaults. Changing planKey can change which modules are entitled, but it does not silently install or remove a tenant module; an incompatible active installation causes a plan-module conflict until an operator resolves it.

Tenant Plans

GET /api/admin/tenant-plans
Authorization: Bearer <organizor-admin-token>

Returns available tenant plans and their default legacy feature settings. Retrieve and manage the plan's module bundle through the dedicated module-entitlement routes documented in Tenant Modules.

PUT /api/admin/tenant-plans/{planKey}
Authorization: Bearer <organizor-admin-token>
Content-Type: application/json

{
  "name": "Pro",
  "description": "Larger customer plan with higher limits and self-service registration.",
  "features": {
    "registration.selfService": true
  },
  "settings": {
    "limits": {
      "maxUsers": 0,
      "maxCamps": 25
    }
  },
  "isActive": true,
  "sortOrder": 20
}

Plan updates replace editable metadata, legacy feature defaults, setting defaults, active state, and sort order. Existing tenant overrides remain intact. Module entitlements are a separate atomic operation so arbitrary feature JSON cannot become the module system.
