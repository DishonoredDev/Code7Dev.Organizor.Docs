Role-Based Authorization

Overview

The API authorizes requests with ASP.NET Core policies backed by Keycloak roles. Authentication validates the JWT first, tenant access middleware enforces tenant membership next, and endpoint authorization policies run after that.

Roles

Role Purpose
organizor-admin Platform administrator. Can manage tenants and call admin operations.
tenant-admin Tenant administrator. Can use tenant-aware application endpoints and tenant catalog reads.
tenant-user Tenant member. Can use shared tenant-aware application endpoints and tenant catalog reads.

JWT Role Sources

The API maps these Keycloak claim shapes to ASP.NET Core role claims:

{
  "realm_access": {
    "roles": ["organizor-admin"]
  },
  "resource_access": {
    "organizor-api": {
      "roles": ["tenant-user"]
    }
  }
}

Only client roles under resource_access.organizor-api.roles are promoted. Roles for other clients, such as account, are ignored for API authorization.

Policies

Policy Accepted roles
RequireOrganizorAdminRole organizor-admin
RequireTenantUserRole organizor-admin, tenant-admin, tenant-user
RequireTenantAdminRole organizor-admin, tenant-admin

Use policies for new endpoints unless the endpoint is intentionally authentication-only.

[Authorize(Policy = AuthorizationPolicies.RequireOrganizorAdminRole)]

Current Endpoint Enforcement

Endpoint area Policy
/api/admin/tenants/* RequireOrganizorAdminRole
/api/admin/tenant-plans/* RequireOrganizorAdminRole
POST /api/v1/tenants RequireOrganizorAdminRole
GET /api/v1/tenants RequireTenantUserRole
GET /api/v1/tenants/{slug} RequireTenantUserRole
GET /api/v1/tenant/config RequireTenantAdminRole
POST /api/public/register anonymous
GET /api/auth/whoami authenticated user only

Tenant Interaction

Role checks do not replace tenant checks. For tenant-scoped routes, a user must pass both:

  • Tenant authorization in TenantAccessMiddleware.
  • Endpoint role or policy authorization in ASP.NET Core.

This means a tenant-user token for acme is still denied when it sends X-Tenant-Slug: contoso.

Assigning Roles in Keycloak

Realm roles are assigned from the user details screen:

  1. Open Keycloak Admin Console.
  2. Select the organizor-dev realm.
  3. Open Users and select the user.
  4. Open Role mapping.
  5. Assign one of organizor-admin, tenant-admin, or tenant-user.

Client roles can also be assigned under the organizor-api client. If client roles are used, verify they appear in resource_access.organizor-api.roles.
