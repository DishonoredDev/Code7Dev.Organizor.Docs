Portal UI Structure — High-Level

The Portal UI is organized into pages, layouts, components, services, and models.

Pages

Page Route Responsibility
Home / Neutral entry page. Authenticated users can be redirected by role.
Authentication /authentication/* Blazor WebAssembly OIDC login/logout callbacks.
Logout /logout Convenience route that starts Blazor OIDC logout and returns to /.
Admin/Dashboard /admin Admin dashboard placeholder.
Admin/Tenants /admin/tenants Operational tenant catalog and lifecycle management.
Admin/Plans /admin/plans Tenant plan default management.
Admin/Users /admin/users?tenantId={id} Platform control-plane user management for one active tenant.
TenantAdmin/Dashboard /tenant Tenant dashboard placeholder.
TenantAdmin/Users /tenant/users Tenant-scoped user management.
TenantAdmin/Config /tenant/config Tenant-admin effective tenant configuration.
TenantShared/Profile /tenant/profile Shared read-only profile for tenant admins and tenant users.
Register /register Temporary public self-registration shell.
NotFound fallback Not-found page.

Tenant-admin-only pages live under Pages/TenantAdmin. Shared tenant pages live under Pages/TenantShared. This keeps future tenant-user-specific pages separate from tenant platform administration.

Layouts

Layout Responsibility
MainLayout General shell with login/logout controls and authenticated user context.
AdminLayout Admin control-plane shell with dashboard, tenant management, plan management, current-user panel, logout, and tenant website navigation when available.
TenantLayout Tenant shell with role-aware tenant navigation, current-user panel, logout, and public-site navigation.

Components

Component Responsibility
UserInfo Displays tenant, username, email, and Keycloak groups from the current authentication state.
CurrentUserPanel Sidebar user card used in admin and tenant shells. Shows display name, email, tenant, groups, logout, and tenant website navigation when available.
LogoutButton Starts Blazor OIDC logout through NavigateToLogout("authentication/logout", "/").
RoleRedirector Redirects authenticated users from neutral entry routes to /admin, /tenant, or /tenant/profile based on role.
RedirectToLogin Sends unauthenticated users to the Blazor OIDC login route.
AuthStateProvider Auth-related component wrapper used by the portal.
AdminSidebar Admin navigation component retained for admin navigation reuse.
UserCreateForm Shared user-create form used by platform and tenant user-management pages.
UserGrid Shared user grid used by platform and tenant user-management pages.

Radzen Usage

The portal references Radzen.Blazor and wires RadzenComponents in App.razor.

The admin tenant page currently uses:

  • RadzenDataGrid for tenant catalog display;
  • RadzenTemplateForm, RadzenTextBox, RadzenTextArea, and validators for tenant onboarding and deletion input;
  • RadzenCard for layout panels;
  • RadzenButton for actions;
  • RadzenBadge for tenant status;
  • RadzenAlert and NotificationService for errors and operation feedback.

Radzen services registered in Program.cs:

  • DialogService
  • NotificationService
  • TooltipService
  • ContextMenuService

Services

Service Responsibility
UserContextService Reads AuthenticationState and maps claims into UserInfoModel.
ApiAuthorizationMessageHandler Attaches access tokens to API requests and adds tenant header context when available.
AdminTenantService Typed client for admin tenant, plan, config inspection, override, and platform user-management operations.
TenantUserService Typed client for tenant-scoped user-management operations used by /tenant/users.
TenantConfigService Typed client for the tenant-scoped effective config endpoint used by tenant admins at /tenant/config.
PublicRegistrationService Typed client for anonymous tenant-user self-registration from /register.
PublicTenantAuthService Typed client for anonymous tenant auth discovery used to resolve the tenant website link.
KeycloakClaimsPrincipalFactory Promotes Keycloak roles into Blazor role claims.

Models

Model Purpose
UserInfoModel Display model for signed-in user context.
TenantModel Portal-side tenant catalog projection.
TenantOnboardingForm Validated form model for tenant onboarding.
TenantOnboardingRequest API request body for onboarding.
TenantSoftDeleteRequest API request body for soft deletion.
TenantMigrationResult API response model for tenant database upgrades.
TenantEffectiveConfigModel Effective tenant config response model used by tenant and admin config views.
TenantPlanModel Tenant plan defaults model used by /admin/plans.
TenantConfigOverridesModel Tenant plan assignment and override model used by /admin/tenants.
TenantUserModel Portal-side Keycloak tenant-user projection.
TenantUserRegistrationForm Public registration form model used by /register.

TenantModel mirrors the API tenant response used by the admin grid: Id, Name, Slug, DatabaseName, CreatedAt, Status, FailureReason, and IsDeleted.

Extension Rules

  • Add page-level authorization attributes to protected pages.
  • Keep API calls inside services instead of Razor markup.
  • Use the named api HttpClient for backend calls so tokens are attached consistently.
  • Avoid forcing full page reloads for internal route redirects unless a complete browser reload is required.
  • Do not add UI for operations until the backing API route exists, unless the page is clearly marked as a placeholder.
