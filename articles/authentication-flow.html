Authentication Flow — High‑Level

The Portal UI uses Keycloak to authenticate users and determine what they are allowed to do. The process follows the standard OpenID Connect Authorization Code Flow with PKCE.

What Happens During Login

  1. The user clicks Login.
  2. The Portal redirects the user to Keycloak at https://localhost:8443/realms/organizor-dev.
  3. Keycloak handles the login form and verifies credentials.
  4. After successful login, Keycloak sends the user back to https://localhost:7025/authentication/login-callback.
  5. The Portal receives a secure token and uses it for API requests.

Why Keycloak

  • Centralized user management
  • Role‑based access control
  • Secure token handling
  • Standard OIDC protocol support

What Developers Need to Know

  • The Portal never handles passwords directly.
  • Tokens are automatically attached to API requests.
  • Protected pages require the user to be authenticated.
  • Keycloak configuration determines what each user can access.
  • The organizor-ui Keycloak client must allow https://localhost:7025/* as a redirect URI and https://localhost:7025 as a web origin.
