Authentication Flow — Portal UI

The Portal UI uses Keycloak to authenticate users and determine which shell they should see. The process follows OpenID Connect Authorization Code Flow with PKCE.

Login Flow

  1. The user clicks Login or navigates to a protected route.
  2. The Portal redirects to Keycloak at https://localhost:8443/realms/organizor-dev.
  3. Keycloak validates the credentials.
  4. Keycloak redirects back to https://localhost:7025/authentication/login-callback.
  5. Blazor WebAssembly stores the authenticated state and access token.
  6. KeycloakClaimsPrincipalFactory maps Keycloak roles into Blazor role claims.
  7. RoleRedirector sends the user to the correct shell when they return from the neutral entry routes.

Role Redirects

RoleRedirector currently routes users as follows:

Role Redirect target
organizor-admin /admin
tenant-admin /tenant

The redirector must only redirect from neutral routes such as / and authentication/login-callback. It should not force navigation when the user is already on /admin or /tenant, because forced self-navigation can create a reload loop.

Logout is initiated either by LogoutButton or the /logout route. Both call Blazor WebAssembly authentication through NavigateToLogout("authentication/logout", "/"), which clears the local authentication state and returns the browser to / after the identity-provider logout flow.

Role Claims in the Portal

The portal role factory reads roles from Keycloak claims and adds ClaimTypes.Role entries for Blazor authorization.

Supported sources:

  • realm_access.roles
  • resource_access.organizor-ui.roles

This is separate from API role mapping, where the API also understands roles under resource_access.organizor-api.roles.

Protected Routes

Portal pages use role attributes:

@attribute [Authorize(Roles = "organizor-admin")]

Current route protection:

Route area Required role
/admin organizor-admin
/admin/tenants organizor-admin
/tenant tenant-admin
/tenant/profile tenant-admin

The admin and tenant layouts contain placeholder navigation links for future pages, including /admin/users and /tenant/camps. They are not protected pages yet because this branch does not add Razor pages for those routes.

API Tokens

The Portal never sends credentials to the API. It sends bearer tokens through the configured API HttpClient. The API validates token signature, issuer, expiration, and then applies authorization policies.

The local issuer must be consistent everywhere:

https://localhost:8443/realms/organizor-dev

If the API is configured with http://localhost:8443/realms/organizor-dev, it will reject HTTPS-issued portal tokens with 401 Unauthorized.

Keycloak Client Requirements

The organizor-ui client must allow:

Setting Value
Valid redirect URI https://localhost:7025/*
Web origin https://localhost:7025
Flow Standard flow / Authorization Code with PKCE

Users must receive the appropriate Organizor role before logging in. If roles are changed in Keycloak, log out and back in to refresh the token and claims.

The current-user display reads these claims when present:

Claim Use
preferred_username Display name fallback before email.
email User contact display.
tenant Tenant context and X-Tenant-Slug header source.
groups Sidebar user context display.
