Authentication Flow — Platform And Tenant-Admin Portals

The Blazor Portal has two host-selected modes. The configured control-plane host uses the platform realm (organizor-dev locally) for organizor-admin users. A tenant-admin host resolves its own active tenant before OIDC starts, then uses that tenant's realm-local portal client.

It is not a shared tenant login screen. PJsabbe, TVDK, and later tenants have separate Keycloak realms, identities, credentials, and sessions.

Platform Login Flow

  1. An Organizor administrator clicks Login or navigates to a protected control-plane route.
  2. The portal redirects to the platform realm at https://localhost:8443/realms/organizor-dev.
  3. Keycloak validates the platform administrator's credentials.
  4. Keycloak redirects back to https://localhost:7025/authentication/login-callback.
  5. Blazor WebAssembly stores the authenticated state and access token.
  6. KeycloakClaimsPrincipalFactory maps platform realm roles into Blazor role claims.
  7. RoleRedirector sends a platform organizor-admin to the control-plane shell.

Tenant-Admin Login Flow

  1. A tenant administrator opens that tenant's configured portal host, for example https://localhost:7022 for TVDK.
  2. Before OIDC is registered, the Portal calls GET /api/public/tenant-portals/auth?baseUrl=... using its actual base URL.
  3. The API resolves one active tenant by its catalog-owned portal URL and returns only public OIDC configuration.
  4. The Portal verifies its base URL, callback URL, logout URL, and origin match the contract exactly, then starts Authorization Code Flow with PKCE against that tenant realm.
  5. Keycloak redirects back to the same tenant portal host. A matching tenant-admin is sent to /tenant and can use the tenant administration screens.

The tenant portal never selects a realm from a username, query string, or route. An unknown host fails startup rather than falling back to the platform realm.

Role Redirects

Portal mode Role and issuer Redirect target
Platform host Platform-realm organizor-admin /admin
Platform host Any tenant identity /access-denied
Tenant host Matching tenant-realm tenant-admin /tenant
Tenant host Matching tenant-realm tenant-user That tenant's public website
Tenant host Platform issuer or tenant mismatch /access-denied

Tenant administrators and tenant users do not sign in to the central portal with the platform client. A tenant website starts OIDC from its own host after loading GET /api/public/tenants/{slug}/auth, so TVDK uses tenant-tvdk and tenant-tvdk-web rather than organizor-dev and organizor-ui. The tenant-admin portal instead uses tenant-tvdk-portal. Switching a running platform WebAssembly OIDC registration to a realm selected by query string is not supported.

Logout is initiated by LogoutButton or the /logout route. Both call Blazor WebAssembly authentication through NavigateToLogout("authentication/logout", "/"), which clears local authentication state and returns the browser to the active Portal host after its matching realm logout.

Role Claims

The portal role factory maps roles from the platform token's realm_access.roles claim into ClaimTypes.Role. The local platform import maps the organizor-api audience so platform API calls carry the audience required by the API.

Tenant website clients emit their own realm roles (tenant-admin or tenant-user), the organizor-api audience, and a tenant compatibility claim. The tenant claim is not an authorization boundary; the API binds a tenant request to the token issuer and catalog-owned tenant realm.

Protected Routes

The supported central portal routes require the platform role:

@attribute [Authorize(Roles = "organizor-admin")]
Route area Required role and issuer
/admin platform organizor-admin
/admin/tenants platform organizor-admin
/admin/plans platform organizor-admin
/admin/users platform organizor-admin
/tenant and its child routes matching tenant-realm tenant-admin at the tenant portal host
/register anonymous temporary test shell

Tenant business routes remain API contracts protected by tenant-realm roles. The tenant portal supplies the supported browser entry point for tenant-admin; tenant-specific public websites own regular tenant-user workflows.

API Tokens

The portal never sends credentials to the API. It sends platform-realm bearer tokens through the configured API HttpClient.

The API validates the token signature, expiry, organizor-api audience, and issuer. It accepts only the configured platform issuer or an active catalog tenant issuer. organizor-admin grants platform administration only when it comes from the platform issuer; a tenant realm cannot obtain control-plane access by using the same role name.

The local platform issuer is:

https://localhost:8443/realms/organizor-dev

If the portal logs in through HTTPS but the API Keycloak:BaseUrl uses the old HTTP endpoint, the issuer differs and API requests fail with 401 Unauthorized.

Platform Client Requirements

The platform-realm organizor-ui client must allow:

Setting Value
Valid redirect URI https://localhost:7025/*
Web origin https://localhost:7025
Flow Standard flow / Authorization Code with PKCE
Token audience organizor-api

Platform users must receive organizor-admin in the platform realm before signing in. Log out and back in after a role change so the token and claims refresh.

Tenant Portal Client Requirements

Onboarding tenant tvdk with portal base URL https://localhost:7022 creates tenant-tvdk-portal in tenant-tvdk with these exact values:

Setting Value
Valid redirect URI https://localhost:7022/authentication/login-callback
Post-logout redirect URI https://localhost:7022
Web origin https://localhost:7022
Flow Standard flow / Authorization Code with PKCE S256
Token audience organizor-api

This client is separate from tenant-tvdk-web, even though both are public PKCE clients in the same tenant realm.

Current-User Account Actions

Tenant current-user account actions are realm-local API contracts. A tenant caller uses its own tenant realm token and X-Tenant-Slug; the API then performs the Keycloak operation in the matching realm.

Password-change initiation is exposed as POST /api/v1/tenant/account-actions/change-password and sets Keycloak UPDATE_PASSWORD for the authenticated user. Profile update is exposed as PUT /api/v1/tenant/account-actions/profile and updates only Keycloak firstName and lastName for that realm-local user. Organizor must not collect, store, or log replacement passwords.

These self-service endpoints operate only on the caller's own tenant-realm identity. Platform support manages another tenant user's identity through /api/admin/tenants/{tenantId}/users; it does not use a user's self-service account-action endpoints.

The central platform portal does not provide a tenant-realm login or account screen. Tenant administrator account workflows use that tenant's portal host; regular tenant-user account workflows belong to tenant websites.
