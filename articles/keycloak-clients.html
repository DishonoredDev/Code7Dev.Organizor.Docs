Keycloak Clients

Keycloak clients are scoped to their realm. Client ids may be repeated only when their realm is intentionally different; tenant website client ids remain deterministic because their tenant realm is already unique.

Platform Realm Clients

The local organizor-dev platform realm import creates:

Client Purpose
organizor-ui Public PKCE client for the central Organizor-admin portal. It emits realm roles and the organizor-api audience.
organizor-api Internal API audience/service client for platform automation.

The control-plane Portal host is configured only for the platform realm. It is not a username- or query-driven runtime tenant-realm switcher.

Master-Realm Provisioner

organizor-provisioner is created in the Keycloak master realm by scripts/bootstrap-keycloak-provisioner.ps1. It is a confidential, service-account-only client. The API uses its secret to call Keycloak Admin REST APIs for tenant realm lifecycle; no browser or tenant website uses it.

API configuration:

{
  "Keycloak": {
    "BaseUrl": "https://localhost:8443",
    "PlatformRealm": "organizor-dev",
    "AdminRealm": "master",
    "AdminClientId": "organizor-provisioner",
    "AdminClientSecret": "<deployment secret>"
  }
}

Tenant Realm Clients

Onboarding tenant acme creates tenant-acme and configures:

Client Purpose
organizor-api Internal audience client required by API JWT validation.
tenant-acme-web Public PKCE client for Acme's website, with the onboarding redirect URIs and origins.
tenant-acme-portal Separate public PKCE client for Acme's tenant-admin portal host.

Both tenant public clients:

  • uses Authorization Code with PKCE S256;
  • has direct grants, implicit flow, and service accounts disabled;
  • emits realm roles, aud: organizor-api, and a direct tenant: acme compatibility claim;
  • are deleted as part of deleting the tenant realm.

Tenant websites must obtain their authority and website client id from:

GET /api/public/tenants/{slug}/auth

Tenant portals instead resolve their authority and portal client id by exact current base URL:

GET /api/public/tenant-portals/auth?baseUrl={url-encoded-portal-base-url}

Do not hard-code the old organizor-dev authority in a TVDK/PJsabbe website or tenant portal. The website and portal clients are intentionally separate even when they use the same tenant realm.
