Portal UI Overview

The Portal UI is the Blazor WebAssembly front end for Organizor platform and tenant administration. It handles platform-realm Keycloak sign-in at the control-plane host, tenant-realm Keycloak sign-in at a tenant portal host, public registration testing, and authenticated API calls to the backend.

The Portal is deliberately not a shared-realm tenant login. It selects a mode once at startup from its actual host: Portal:PlatformBaseUrl uses static platform OIDC configuration, while every other host must resolve an exact tenant portal runtime contract before it starts OIDC.

Technology Stack

  • Blazor WebAssembly for client-side rendering.
  • .NET 10 for the portal project.
  • Keycloak for authentication using OIDC Authorization Code Flow with PKCE.
  • Radzen.Blazor for the admin tenant grid, cards, forms, buttons, badges, alerts, and notifications.
  • IHttpClientFactory plus a custom AuthorizationMessageHandler for API calls.

Routes and Layouts

AdminLayout groups platform navigation into Overview and Platform sections. TenantLayout is served only through the matching tenant portal host after tenant-realm sign-in; the control-plane host does not route tenant administrators into it.

RoleRedirector is mounted globally in App.razor, but it only redirects from neutral entry routes (/ and the login callback). In platform mode it sends only a platform-realm organizor-admin to /admin. In tenant mode it verifies the tenant claim and issuer match the resolved portal tenant, then sends a tenant-admin to /tenant; a regular tenant user goes to the configured public website. It must not redirect when the user is already on a target area, otherwise the portal can reload-loop.

Public Registration Shell

The /register page is a temporary public shell for exercising tenant-user self-registration. It posts to POST /api/public/register through PublicRegistrationService.

The long-term model is that tenant-specific static websites own their registration UI and call the public API contract directly. Participant-facing activity registration forms are not backend portal pages. This keeps tenant branding and UX independent from the Organizor portal.

Tenant rows expose the catalog and lifecycle fields used by the UI:

Field Use
id Action target for upgrade and delete calls.
name, slug, databaseName Catalog display and search.
createdAt Created timestamp shown in local time.
status Lifecycle state used for badges and failed counts.
failureReason Failure detail shown below the tenant name when present.
isDeleted Controls deleted badge state and whether hard delete is available.

Summary

The supported portal surface is the platform dashboard, tenant lifecycle operations, tenant plan defaults, tenant-level config overrides, platform tenant-user management, and public registration testing at the control-plane host; and tenant business administration at a matching tenant portal host. Regular tenant-user profile, family, and registration workflows belong in tenant-specific public UIs such as TVDK.
