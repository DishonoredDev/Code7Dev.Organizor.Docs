Background Jobs And Docs Operations

Scheduled Tenant Jobs

Organizor is wired for Quartz recurring background work, but tenant job scheduling is not currently enabled on startup. Program.cs contains a commented-out scheduling block for future use.

The scheduler loads tenants from the catalog database, creates a durable SyncTenantJob per tenant, stores TenantId and TenantSlug in the Quartz job data map, and schedules or replaces the tenant trigger.

Current trigger cadence:

0/10 * * * * ?

That Quartz cron expression would run the tenant synchronization job every 10 seconds when scheduling is enabled.

SyncTenantJob reads tenant data from the job data map, sets ITenantContext, and runs tenant-scoped work through OrganizorDbContext. The current implementation logs execution and contains placeholder synchronization work.

Quartz persistence is stored in the catalog database and uses the PostgreSQL tables added by the AddQuartzTables migration.

Documentation Deployment

The repository contains a GitHub Actions workflow at .github/workflows/docfx-deploy.yml.

On pushes to master, it checks out this repository, installs DocFX, builds docs/docfx.json, checks out the public documentation repository, copies docs/_site, commits, and pushes the generated documentation.

The workflow uses the DOCS_DEPLOY_KEY secret to push to the public docs repository.

Sitemap And Crawlers

DocFX generates docs/_site/sitemap.xml from the build.sitemap.baseUrl value in docs/docfx.json.

The documentation source includes robots.txt, which is copied into the generated site and points crawlers to the sitemap.
