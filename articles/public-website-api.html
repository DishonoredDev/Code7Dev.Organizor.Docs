Public Website API

Public website endpoints are anonymous by design. They return non-secret tenant auth metadata, public activity registration metadata, or create tenant/user-facing records through explicitly public contracts.

Public Activity Registration Discovery

Tenant public websites can list active anonymous-registerable activity-type segments for navigation, list activities for their configured tenant, and load a direct registration form by activity id.

These discovery endpoints require X-Tenant-Slug because they read tenant-scoped activity data from the resolved tenant database.

GET /api/v1/public/activity-types
X-Tenant-Slug: acme
Accept: application/json

Returns active anonymous-registerable activity types that have at least one active public activity. Tenant websites can use this response for segment navigation such as a sidebar.

GET /api/v1/public/activities
X-Tenant-Slug: acme
Accept: application/json

Returns active activities whose activity type is active and uses anonymous registration mode. Each item includes the activity GUID, activity type metadata, display fields, price, image URL when configured, and registration availability. Use GET /api/v1/public/activities?activityTypeKey=swimming to list only one activity-type segment.

GET /api/v1/public/activities/00000000-0000-0000-0000-000000000000/registration-form
X-Tenant-Slug: acme
Accept: application/json

Returns the same public activity display data plus active registration fields. Field options are returned as public option objects with value and label. The first-slice availability values are open and full.

Public websites submit the completed form through the existing endpoint:

POST /api/v1/activities/00000000-0000-0000-0000-000000000000/public-registrations
X-Tenant-Slug: acme
Content-Type: application/json
Status Meaning
200 OK Public activity metadata or registration form metadata returned.
400 Bad Request Tenant slug is missing/invalid, the activity is inactive, or the activity is not publicly registerable.
404 Not Found Activity or activity type was not found for the resolved tenant.
500 Internal Server Error Unexpected server error. See Errors and Observability.

Static Tenant Website Auth Contract

GET /api/public/tenants/acme/auth
Accept: application/json

Returns the public OIDC settings a tenant-specific website needs before login. The endpoint returns data only for active, non-deleted tenants.

Example response:

{
  "tenantSlug": "acme",
  "authority": "https://localhost:8443/realms/tenant-acme",
  "clientId": "tenant-acme-web",
  "websiteBaseUrl": "https://acme.example.com",
  "responseType": "code",
  "usePkce": true,
  "tenantHeaderName": "X-Tenant-Slug",
  "tenantClaimName": "tenant",
  "tenantUserRole": "tenant-user",
  "tenantAdminRole": "tenant-admin",
  "tenantUserGroupPath": "/users",
  "tenantAdminGroupPath": "/admins",
  "scopes": ["openid", "profile", "email"],
  "loginRedirectUris": ["https://acme.example.com/authentication/login-callback"],
  "logoutRedirectUris": ["https://acme.example.com"],
  "webOrigins": ["https://acme.example.com"],
  "registrationRedirectUrl": "https://acme.example.com/register/complete",
  "publicRegistrationEndpoint": "/api/public/register"
}

The authority is the catalog tenant's own Keycloak realm. A PJsabbe website receives tenant-pjsabbe; a TVDK website receives tenant-tvdk. Do not replace that authority with the platform realm or hard-code a shared realm in a tenant website.

Static tenant websites use this contract during startup to configure OIDC Authorization Code Flow with PKCE, select the generated tenant client id, request openid profile email, and send X-Tenant-Slug on authenticated tenant-scoped API calls after login. They derive callback and logout URLs from their own deployed base URL and must verify those URLs and their browser origin appear in the contract before they start login. A mismatch is an onboarding/deployment configuration problem; never fall back to the platform authority or client.

Tenant website tokens contain realm-local tenant-user or tenant-admin roles and an organizor-api audience. They may also contain tenant: acme for client compatibility, but the API authorizes using the issuer-to-tenant binding, not that claim or the group-path strings.

Status Meaning
200 OK Contract returned for an active tenant.
400 Bad Request Tenant slug or stored auth settings are invalid.
404 Not Found Tenant does not exist, is deleted, or is not active.

Tenant-Admin Portal Auth Contract

GET /api/public/tenant-portals/auth?baseUrl=https%3A%2F%2Flocalhost%3A7022
Accept: application/json

This anonymous endpoint exists so the Portal can configure OIDC before a tenant administrator signs in. It normalizes the supplied base URL, resolves exactly one active tenant by its catalog-owned AdminPortalBaseUrl, and returns only public client metadata.

{
  "tenantSlug": "tvdk",
  "authority": "https://localhost:8443/realms/tenant-tvdk",
  "clientId": "tenant-tvdk-portal",
  "websiteBaseUrl": "https://localhost:7122",
  "responseType": "code",
  "usePkce": true,
  "scopes": ["openid", "profile", "email"],
  "loginRedirectUri": "https://localhost:7022/authentication/login-callback",
  "logoutRedirectUri": "https://localhost:7022",
  "webOrigin": "https://localhost:7022"
}

The Portal validates its actual base URL, callback URL, logout URL, and origin against this contract before starting OIDC. An unknown or inactive portal URL returns TENANT_NOT_FOUND; an invalid URL returns TENANT_CONFIG_INVALID. The endpoint never returns a secret, Keycloak administration credential, or platform OIDC configuration.

Public Tenant User Registration

POST /api/public/register
Content-Type: application/json

{
  "tenantSlug": "acme",
  "username": "jane.doe",
  "email": "jane@example.com",
  "password": "correct-horse-battery-staple"
}

Creates an enabled tenant-user account for an active tenant. This endpoint does not use X-Tenant-Slug; the tenant is selected from the request body.

Registration creates the identity in the tenant's own Keycloak realm and assigns it to realm-local /users. The API validates that the tenant exists, is active, has effective settings.registration.enabled set to boolean true, and has not reached its configured user limit. Username and email uniqueness are evaluated inside that realm, so the same login name can exist independently in another tenant realm.

The portal /register page is a temporary shell for testing this feature. Tenant-specific websites should provide their own UI and call this API contract directly. Tenant administrators use their tenant-specific Portal host rather than the public website client.

Status Meaning
200 OK User was created and assigned to the realm-local tenant-user group.
400 Bad Request Request validation failed, effective registration config is invalid, or registration is disabled.
404 Not Found Tenant slug does not resolve to an active tenant.
409 Conflict Username or email already exists in that tenant realm, or the tenant user limit was reached.
502 Bad Gateway Keycloak rejected the user operation or could not complete it.
500 Internal Server Error Unexpected server error. See Errors and Observability.
