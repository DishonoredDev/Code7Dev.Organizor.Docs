Public API Behavior

The public API exposes tenant catalog endpoints, tenant-scoped config reads, anonymous tenant-user self-registration, and static tenant website authentication discovery. Tenant catalog endpoints are platform/catalog routes, so tenant resolution does not require X-Tenant-Slug for them. They are still authenticated:

  • POST /api/v1/tenants requires organizor-admin.
  • GET /api/v1/tenants and GET /api/v1/tenants/{slug} require organizor-admin, tenant-admin, or tenant-user.

Tenant-scoped application endpoints, including GET /api/v1/tenant/config and tenant user-management routes, must include the X-Tenant-Slug header unless the path is explicitly skipped by tenant resolution.

Internal tenant administration endpoints are documented separately in Internal Operations.

Static Tenant Website Auth Contract

GET /api/public/tenants/acme/auth
Accept: application/json

Returns the public OIDC settings a tenant-specific static website needs before login. The endpoint is anonymous and only returns data for active, non-deleted tenants.

Example response:

{
  "tenantSlug": "acme",
  "authority": "https://localhost:8443/realms/organizor-dev",
  "clientId": "tenant-acme-web",
  "websiteBaseUrl": "https://acme.example.com",
  "responseType": "code",
  "usePkce": true,
  "tenantHeaderName": "X-Tenant-Slug",
  "tenantClaimName": "tenant",
  "tenantUserRole": "tenant-user",
  "tenantAdminRole": "tenant-admin",
  "tenantUserGroupPath": "/tenants/acme/users",
  "tenantAdminGroupPath": "/tenants/acme/admins",
  "scopes": ["openid", "profile", "email"],
  "loginRedirectUris": [
    "https://acme.example.com/authentication/login-callback"
  ],
  "logoutRedirectUris": [
    "https://acme.example.com"
  ],
  "webOrigins": [
    "https://acme.example.com"
  ],
  "registrationRedirectUrl": "https://acme.example.com/register/complete",
  "publicRegistrationEndpoint": "/api/public/register"
}

Static tenant websites should use this contract to:

  • configure OIDC Authorization Code Flow with PKCE;
  • link back to the tenant website using websiteBaseUrl;
  • use the generated tenant client id;
  • request openid profile email;
  • send X-Tenant-Slug: {tenantSlug} on tenant-scoped authenticated API calls;
  • expect the Keycloak token to contain a tenant claim from the tenant-membership mapper.
  • expect user tokens to be members of /tenants/{tenantSlug}/users or /tenants/{tenantSlug}/admins and to carry the matching tenant-user or tenant-admin role required by the target endpoint.

Possible responses:

Status Meaning
200 OK Contract returned for an active tenant.
400 Bad Request Tenant slug or stored auth settings are invalid.
404 Not Found Tenant does not exist, is deleted, or is not active.

Public Tenant User Registration

POST /api/public/register
Content-Type: application/json

{
  "tenantSlug": "acme",
  "username": "jane.doe",
  "email": "jane@example.com",
  "password": "correct-horse-battery-staple"
}

Creates an enabled tenant-user account for an active tenant. This endpoint is anonymous and does not use X-Tenant-Slug; the tenant is selected from the request body.

Registration uses Keycloak as the source of truth and assigns the user to /tenants/{slug}/users. The API validates the tenant exists, is active, has effective settings.registration.enabled set to boolean true, and has not reached its configured user limit.

The portal /register page is only a temporary shell for testing this feature. Future tenant-specific static websites should provide their own UI and call this API contract directly.

Possible responses:

Status Meaning
200 OK User was created and assigned to the tenant user group.
400 Bad Request Request validation failed, effective registration config is invalid, or registration is disabled.
404 Not Found Tenant slug does not resolve to an active tenant.
409 Conflict Username or email already exists in Keycloak, or the tenant user limit was reached.
502 Bad Gateway Keycloak rejected the user operation or could not complete it.
500 Internal Server Error Unexpected server error. See Errors and Observability.

Tenant Catalog

Create Tenant

POST /api/v1/tenants
Authorization: Bearer <organizor-admin-token>
Content-Type: application/json

{
  "name": "Acme",
  "slug": "acme"
}

Creates a catalog tenant record with Pending status and returns tenant metadata. This route does not provision Keycloak groups, a default tenant admin, or a tenant database. Use POST /api/admin/tenants/onboard for the full onboarding workflow.

Example response:

{
  "id": "11111111-1111-1111-1111-111111111111",
  "name": "Acme",
  "slug": "acme",
  "databaseName": "organizor_tenant_acme",
  "createdAt": "2026-06-09T10:30:00Z",
  "status": "Pending",
  "failureReason": null,
  "isDeleted": false
}

All tenant catalog responses use the same shape:

Field Meaning
id Tenant catalog identifier.
name Human-readable tenant name.
slug Stable slug used for lookup and tenant routing.
databaseName Tenant database name assigned by the catalog.
createdAt UTC catalog creation timestamp.
status Current lifecycle status, such as Pending, Active, Failed, or Deleted.
failureReason Provisioning or lifecycle failure detail when available.
isDeleted Whether the catalog record has been soft-deleted. Public reads exclude deleted records.

Possible responses:

Status Meaning
200 OK Tenant catalog record was created.
401 Unauthorized Missing or invalid bearer token.
403 Forbidden Token does not satisfy the organizor-admin role policy.
409 Conflict Duplicate tenant slug.
500 Internal Server Error Unexpected server error. See Errors and Observability.

Get Tenant By Slug

GET /api/v1/tenants/acme
Authorization: Bearer <token>

Returns a tenant by slug using the tenant catalog response shape above, or 404 Not Found when no tenant exists. Soft-deleted tenants are excluded.

List Tenants

GET /api/v1/tenants
Authorization: Bearer <token>

Returns all catalog tenants visible through the tenant repository using the tenant catalog response shape above. Soft-deleted tenants are excluded.

Tenant Config

GET /api/v1/tenant/config
Authorization: Bearer <tenant-token>
X-Tenant-Slug: acme

Returns the current tenant's effective config. Effective config is resolved from the tenant's assigned plan defaults plus tenant-specific overrides.

This endpoint requires organizor-admin or tenant-admin through the RequireTenantAdminRole policy. Tenant access middleware also verifies that the authenticated user belongs to the tenant identified by X-Tenant-Slug.
