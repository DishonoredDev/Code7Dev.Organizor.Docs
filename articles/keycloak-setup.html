Keycloak Setup

Organizor uses one Keycloak deployment and database, with identity isolation at the realm boundary:

  • organizor-dev is the local platform realm. It contains Organizor administrators and the central portal client.
  • tenant-{slug} is created for every tenant. For example, PJsabbe uses tenant-pjsabbe; TVDK uses tenant-tvdk.
  • master contains the backend-only provisioning service account. It is not an application login realm.

Use Keycloak HTTPS Setup before configuring clients or testing login. With an empty Keycloak database, Docker Compose imports docker/keycloak/import/organizor-dev-realm.json, which creates only platform resources.

Local Provisioner Bootstrap

After starting a fresh Keycloak database, create the master-realm service account used by the API:

pwsh ./scripts/bootstrap-keycloak-provisioner.ps1 -SkipCertificateCheck

The script reads the Keycloak admin and provisioner values from .env; it does not print the provisioner secret. Configure the API with matching user secrets:

dotnet user-secrets set "Keycloak:BaseUrl" "https://localhost:8443" --project .\Code7Dev.Organizor.Api\Code7Dev.Organizor.Api.csproj
dotnet user-secrets set "Keycloak:PlatformRealm" "organizor-dev" --project .\Code7Dev.Organizor.Api\Code7Dev.Organizor.Api.csproj
dotnet user-secrets set "Keycloak:AdminRealm" "master" --project .\Code7Dev.Organizor.Api\Code7Dev.Organizor.Api.csproj
dotnet user-secrets set "Keycloak:AdminClientId" "organizor-provisioner" --project .\Code7Dev.Organizor.Api\Code7Dev.Organizor.Api.csproj
dotnet user-secrets set "Keycloak:AdminClientSecret" "<value from .env>" --project .\Code7Dev.Organizor.Api\Code7Dev.Organizor.Api.csproj

The provisioner has Keycloak server-administration permissions because it must create and delete arbitrary tenant realms. Treat its client secret like production infrastructure credentials: store it only in backend deployment secrets, never in portal or tenant-website configuration.

Reset Behavior

docker compose --env-file .\.env down -v removes the local Keycloak database volume only. The next up -d imports the platform realm again. Run the provisioner bootstrap script again before onboarding tenants. It does not remove the Organizor catalog or tenant PostgreSQL databases; use the clearly destructive Full Local Test Reset procedure when a completely fresh test environment is intended.
