Localization

Organizor provides multilingual support for error responses using a simple, predictable, API-friendly localization pipeline.

Supported Languages

Organizor currently supports:

  • en - English (fallback)
  • nl - Dutch

Additional languages can be added by creating new resource files in the Code7Dev.Organizor.Api/Resources folder.

How Localization Works

Localization is driven by the standard Accept-Language HTTP header.

Example:

Accept-Language: nl

The API resolves the culture for the request and uses it to translate error messages. If a translation is missing, the system falls back to English (en).

Key Principles

  • Application services return error codes only, such as TENANT_NOT_FOUND.
  • The API middleware maps those codes to localized resource strings.
  • No hardcoded user-facing messages exist in the domain or application layers.
  • Localization is deterministic and client-controlled.

Culture Resolution

Organizor uses the following resolution order:

  • Accept-Language header.
  • Fallback to English (en).

This keeps behavior predictable and client-controlled.

Error Code Translation

Each error code corresponds to a resource key.

Examples:

  • TENANT_NOT_FOUND
  • TENANT_ALREADY_EXISTS
  • UNEXPECTED_ERROR

These keys exist in:

  • Code7Dev.Organizor.Api/Resources/Shared.en.resx
  • Code7Dev.Organizor.Api/Resources/Shared.nl.resx

The middleware retrieves the localized string and injects it into the RFC 7807 problem response.

Example Request and Response

Request:

GET /api/v1/tenants/unknown
Authorization: Bearer <token>
Accept-Language: nl

Response:

{
  "type": "https://httpstatuses.com/404",
  "title": "Tenant niet gevonden",
  "status": 404,
  "error": "TENANT_NOT_FOUND",
  "correlationId": "abc123"
}

The error code remains stable and language-independent. The title is localized based on the request culture.

Adding New Translations

To add a new language:

  1. Create a new .resx file, for example Shared.fr.resx.
  2. Add the same error keys as in the English file.
  3. Provide translated values.
  4. Register the culture in AddApiLocalization.
  5. Restart the API.
