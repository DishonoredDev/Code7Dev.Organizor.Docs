Portal Admin Workflows

Platform administration routes use AdminLayout and require organizor-admin issued by the configured platform realm. The admin shell groups navigation into Overview and Platform sections, with /admin/users intentionally remaining a tenant-row deep link rather than a standalone sidebar item. A platform administrator has one control-plane login; the backend provisioner manages separate tenant realms without giving the administrator tenant or master credentials.

Dashboard

The /admin dashboard is a read-only platform overview. It loads tenant and plan data through AdminTenantService, summarizes tenant lifecycle state, highlights failed tenant records, shows active and inactive plan counts, and links to tenant and plan management.

The dashboard does not add new API endpoints or mutate tenant data.

Tenant Management

The admin tenant page uses Radzen components and the AdminTenantService client. It supports:

  • loading all tenants including soft-deleted tenants;
  • filtering tenants by name, slug, database name, or status;
  • viewing active, deleted, and failed tenant counts;
  • onboarding a tenant with website and auth metadata;
  • upgrading a tenant database by running pending migrations;
  • soft-deleting a tenant with an operator reason;
  • hard-deleting a previously soft-deleted tenant;
  • opening user management for active tenants;
  • inspecting effective tenant config;
  • editing tenant plan assignment and tenant-level overrides.
  • inspecting a tenant's entitled and installed modules;
  • installing an optional add-on, retrying a failed or interrupted installation, or enabling/disabling an installed module without deleting its business data.
UI action API endpoint

Load one tenant GET /api/admin/tenants/{id}
Onboard tenant POST /api/admin/tenants/onboard
Upgrade tenant POST /api/admin/tenants/{id}/upgrade
Inspect effective config GET /api/admin/tenants/{id}/config
Load tenant overrides GET /api/admin/tenants/{id}/config-overrides
Save tenant overrides PUT /api/admin/tenants/{id}/config-overrides
Inspect tenant modules GET /api/admin/tenants/{id}/modules
Install tenant module POST /api/admin/tenants/{id}/modules/{moduleKey}/install
Retry failed or interrupted module installation POST /api/admin/tenants/{id}/modules/{moduleKey}/retry
Enable tenant module POST /api/admin/tenants/{id}/modules/{moduleKey}/enable
Disable tenant module POST /api/admin/tenants/{id}/modules/{moduleKey}/disable
Soft delete tenant DELETE /api/admin/tenants/{id}
Hard delete tenant POST /api/admin/tenants/{id}/hard-delete

Tenant onboarding stores website/auth settings in centralized tenant config, assigns immutable IdentityRealm tenant-{slug}, and provisions that realm so tenant website auth can use Organizor as the source of truth. The onboarding dialog also selects an active plan; successful onboarding automatically installs that plan's included modules.

Soft delete disables the tenant realm before catalog deletion state is recorded. Hard delete removes the complete tenant realm before database and catalog cleanup. An identity-provider failure stops the destructive action and is surfaced as TENANT_IDENTITY_PROVIDER_FAILED.

The tenant drawer separates Modules from legacy configuration. Its module section shows plan availability, installation state, source, dependency readiness, and any failure reason. A disabled module retains data, and a module with an enabled dependent cannot be disabled.

Plan Management

The admin plans page uses AdminTenantService and supports loading and editing tenant plan definitions. Its Modules tab manages the plan's product bundle separately from legacy feature and settings defaults.

UI action API endpoint
Load plans GET /api/admin/tenant-plans
Save plan defaults PUT /api/admin/tenant-plans/{planKey}
Load deployed module catalog GET /api/admin/modules
Load plan module entitlements GET /api/admin/tenant-plans/{planKey}/module-entitlements
Save plan module entitlements PUT /api/admin/tenant-plans/{planKey}/module-entitlements

Plan keys are intentionally immutable. The entitlement editor assigns every deployed module one of Included, Optional add-on, or Unavailable. An included module is installed at successful onboarding; an optional module needs an explicit tenant action. See Tenant Modules for the lifecycle constraints.

Tenant User Control Plane

The tenant catalog page is the entry point for platform tenant-user management. Platform administrators open users from an active tenant row, which navigates to /admin/users?tenantId={id}.

The admin users page manages only that tenant's realm-local Keycloak users. It can create users, list users, toggle enabled state, delete users, and assign tenant roles within the selected tenant. The same username may exist in another tenant realm without being the same identity.

The admin sidebar does not expose /admin/users as a standalone global directory. /admin/users without a valid active tenant id redirects to /admin/tenants.
